# JIDU6111 driver audit, 26 November 2026

Searches returned 318 distinct OpenWrt pull requests across Qualcomm target, board and SoC, Wi-Fi, Ethernet, shared networking and platform support. The platform search included WCSS, PCIe, NAND, USB and thermal changes. Follow-up searches covered netifd, hostapd and Wi-Fi configuration. The review also checked the Qualcomm board-data repository and the upstream Linux ath11k, PPE and QCA807x histories. OpenWrt main remains at `f76496253dfc`, and mac80211 backports remain on 7.2. The build pins the updated [JIDU6111 board support](https://github.com/openwrt/openwrt/commit/727ed7916a1df588a5a325119e837fec5483c062), which adds the WAN-derived label MAC alias and bumps the U-Boot tools package release.

The build uses the generic and mac80211 changes from #26893. It takes the multicast-table fix from #26122, the ath11k portions of #25807 and #26253, the retry-statistics patch from #25982, and the late-interface hotplug fix from #26655. The remaining changes cover another SoC, drivers outside the image, older mac80211 patch context, or packet-steering policy. The previously included patch content matched the current versions of those PRs.


The WMI recovery patch follows [ath-next v3 05/13](https://lore.kernel.org/r/20261121230731.1206043-6-julius@bairaktaris.de) on the pinned 7.2 backport. Patch 954 initializes all CE descriptor queues at allocation, before recovery can wake them. The QMI server-exit path sets recovery before cleanup. For PCI resets, the reset worker sets it before cleanup since QMI reports server exit later. Both WMI wait predicates exit with `-ESHUTDOWN` when a normal sender retries during recovery. The restart worker can still send setup commands, and successful firmware reconfiguration clears the flag before mac80211 resumes. QMI FW_READY clears it only on initial registration.

## Other relevant results

- The cross-radio workaround in [#26199](https://github.com/openwrt/openwrt/pull/26199) targets firmware tested on IPQ8074. It tears down the established association before the new one succeeds. JIDU6111 keeps standard hostapd association handling and includes the separate same-radio ath11k fix from [#25520](https://github.com/openwrt/openwrt/pull/25520), tested upstream on IPQ9574.

- Backports already include the receive coalescing fix in [#24658](https://github.com/openwrt/openwrt/pull/24658), the recent upstream ath11k management-TX and regulatory fixes, and the equivalent locked mac80211 access discussed in [#26056](https://github.com/openwrt/openwrt/pull/26056). The Ethernet receive fix in #25569 covers the same freed-buffer path as [#24191](https://github.com/openwrt/openwrt/pull/24191). The earlier firmware already applied a compatible RXDMA isolation backport from [#24254](https://github.com/openwrt/openwrt/pull/24254).
- JIDU6111 uses PSGMII. [#26007](https://github.com/openwrt/openwrt/pull/26007) addresses a QSGMII-specific PHY sequence. Linux 6.18.65 includes the checked QCA807x GPIO return and DSP bias fixes. Shared IPQ5018/QCN6122, ath12k and qca8k changes target different devices or drivers.
- The build keeps the board definition from [#26498](https://github.com/openwrt/openwrt/pull/26498). [#26551](https://github.com/openwrt/openwrt/pull/26551) and [#25869](https://github.com/openwrt/openwrt/pull/25869) are alternative board ports with their own device tree and upgrade logic. Both shipped calibration files match [board-data PR #193](https://github.com/openwrt/firmware_qca-wireless/pull/193) byte for byte.
- [#21495](https://github.com/openwrt/openwrt/pull/21495) and [#24713](https://github.com/openwrt/openwrt/pull/24713) propose alternative memory changes. The images use the existing smaller RX rings with private RXDMA caches. [#24178](https://github.com/openwrt/openwrt/pull/24178), [#26075](https://github.com/openwrt/openwrt/pull/26075) and [#25981](https://github.com/openwrt/openwrt/pull/25981) are offload, fast-path or scheduler redesigns. [#26959](https://github.com/openwrt/openwrt/pull/26959) changes unencrypted mesh setup across three packages. The hardware mode, 6 GHz and alternate board-data submissions target modes or board configurations outside these JIDU6111 profiles.
- [#26613](https://github.com/openwrt/openwrt/pull/26613) covers the AP multicast default in [#24641](https://github.com/openwrt/openwrt/pull/24641) and handles isolation aliases and VLANs. [#26876](https://github.com/openwrt/openwrt/pull/26876) is the 24.10 backport of radio recovery. [#26938](https://github.com/openwrt/openwrt/pull/26938) has an equivalent fix in the main pin. The ath11k changes in the [linux-firmware update](https://github.com/openwrt/openwrt/pull/26941) target QCA2066 and leave the JIDU6111 radio firmware unchanged.
- The [EHT options](https://github.com/openwrt/openwrt/pull/26924), [multi-radio wiphy power settings](https://github.com/openwrt/openwrt/pull/26325) and [fullmac handling](https://github.com/openwrt/openwrt/pull/26004) target hardware or configurations outside these images. The [FT replay cache](https://github.com/openwrt/openwrt/pull/26455) needs combined roaming validation with the existing FT changes. [#26668](https://github.com/openwrt/openwrt/pull/26668) changes overall threaded NAPI steering policy.
- [#26920](https://github.com/openwrt/openwrt/pull/26920) reorders monitor-interface setup and needs hardware testing alongside AP and monitor modes. [#25234](https://github.com/openwrt/openwrt/pull/25234) fixes sparse CPU IDs, while this board has four consecutive IDs. [#26815](https://github.com/openwrt/openwrt/pull/26815) changes a hostapd VLAN path available with full wpad; this profile builds the basic variant. [#24253](https://github.com/openwrt/openwrt/pull/24253) rewrites M3 loading for IPQ5018/QCN6122.
